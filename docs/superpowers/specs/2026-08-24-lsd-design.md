# ytk lsd — orthogonal idea generation as an experiment-backed feature

Source: Garry Tan's "LSD mode" (Lateral Syntactic Drift), ingested as
`sources/instagram/ycomclips-2026-08-24-DcbbpsdjI12.md`. The claim: forbid
combining concepts inside the similarity cone, raise randomness on the
retrieval step, generate hundreds of orthogonal combinations, rank by
coherence, and the top 5 of 100 are reliably strong.

## What the record already says

- Section 12: every note sits at cosine 0.51 from a shared direction. Measured
  again on 431 YouTube notes: |mean| 0.516, random-pair raw cosine median
  0.25, 1st percentile 0.09; only 1.5% of pairs have |cos| < 0.1. Centred, the
  median is -0.014 and 76% of pairs sit under 0.1. "Orthogonal" is empty in
  raw space and the default after centering, so the rule needs a measured
  scale, not a literal zero.
- Section 50: the background-pair null std, T = 0.106, is already the
  temperature wherever ranked winners are shown. It is the sampling
  temperature here.
- Sections 20 and 36: roads between interests run through hubs; the biggest
  hub is in 63 of 568 top-10 lists and hubness rides on the cone. The
  combination must be generated by the model from two sampled notes, never
  retrieved from the index as "the note between them".
- Section 18: the corpus voice is literal. A coherence ranker with no null
  will prefer the cone back.

## Decisions (owner, 2026-08-24)

- Pair unit: source notes first (centred doc vectors); SAE latents are rung 1
  once rung 0 passes.
- Output: both kinds per pair, tagged — a `build` idea (project / experiment /
  tool) and a `post` angle (writeup hook / video angle).
- Ground truth: the owner's blind ratings, pool hidden, on a hub deck.
- Surface: hub page `/lsd`. Deferred: no UI page ships without explicit
  approval. Rung 0 runs the experiment and freezes a deck; the page follows.
- Method: matplotlib checkpoints and the math drawn at every stage before the
  stage after it is built.

## Modules

```
ytk/lsd.py                      sampler -> generator -> judge -> deck; pure functions over arrays + sdk
scripts/lsd_checkpoints.py      C0..C6 figures, house style, from the run file and the store
docs/assets/53-lsd/README.md    pre-registration first, one paragraph per checkpoint as it lands
~/.ytk/lsd/runs/<run_id>.json   immutable: pairs, cosines, candidates, judge scores, pool labels
~/.ytk/lsd/ratings.jsonl        run_id, candidate_id, score 1-5, note, ts
```

Only the scorer joins ratings to pool labels. The deck served to the rater
never carries a pool label, and parent notes are hidden until the card is
rated (a NEAR pair's twin titles would unblind the rater).

## Sampler

Doc pool: `ytk_videos_v2` plus the `note_sources_*` rows of `ytk_memories_v2`
(766 notes today). Centre on the pooled mean, unit-normalise. Three pools of
100 pairs, one seed for the rated run, 20 seeds for judge-only metrics.

- ORTHO: (i, j) uniform, accepted with probability exp(-cos_c / T),
  T = 0.106, rejected outright above the 95th percentile of centred cosine
  (recomputed per run and stored). Uniform base draw, no neighbour call.
- NEAR: i uniform, j uniform among i's top-10 centred neighbours.
- RAND: uniform pairs, no constraint.

Every pair stores raw and centred cosine.

## Generator

One `sdk.structured` call per pair (Haiku, subscription path). Input: each
note's thesis and insights. Output schema: `build` (title, pitch, first
experiment) and `post` (hook, angle). Prompt identical for all pools.
300 calls per run, executed as a background job.

## Judge and novelty

Coherence: Haiku, batches of 10 candidates, rubric 1-5, blind to pool.
Novelty: embed each candidate; store centred cosine to nearest existing note
and to each parent. Neither number decides pass/fail alone.

## Pre-registration

Deck per kind: judge top-5 of each pool (15) + 5 uniform draws from each
pool's remaining 95 (15), shuffled. 60 cards total.

- G1, the yield claim: among ORTHO's judge-top-5, owner score >= 4 on at
  least 3 of 5 for at least one kind, and strictly more than NEAR's top-5 for
  that kind. Fail either bar and LSD mode is not a feature.
- G2, the judge is real: Spearman(judge, owner) >= 0.30 over the 60 cards.
  Fail and the ranker is decoration; rung 1 replaces it before anything else.
- Disclosed, not gated: ORTHO vs RAND; novelty by pool; hub concentration in
  NEAR parents; candidates' cosine to the corpus mean.

## Checkpoint ladder

| # | figure | math it draws | gates |
|---|---|---|---|
| C0 | random-pair cosine, raw vs centred, orthogonal strip shaded | cos(x,y) = |mu|^2 + mu.(r_x + r_y) + r_x.r_y; the constant term is the raw median | centering is mandatory; T has a meaning |
| C1 | acceptance curve exp(-cos_c/T) over the centred distribution; ORTHO vs uniform | one T-unit is one std of "unrelated" | ORTHO differs from RAND before any model call |
| C2 | per-note appearance counts across pools vs section 36 hub counts | uniform base draw keeps hubs out; NEAR concentrates them | sampler is doing its job |
| C3 | three pools on one centred-cosine axis, raw in the meta line | the README's opening figure | pools are frozen |
| C4 | candidate distance to nearest note vs to parents' midpoint, per pool | section 20: midpoints retrieve hubs; new means far from everything | generation produced something outside the corpus |
| C5 | judge vs owner scatter with shuffled-rating null band | Spearman under a permutation null | G2 |
| C6 | pool top-5 hit rates over the 5-card binomial band | "3 of 5" inside or outside chance | G1 |

C0-C4 run in rung 0 without the owner. C5-C6 wait for ratings, which wait
for the approved page.

## Ladder after rung 0

1. SAE-latent sampler as a fourth pool (decoder cosine ~ 0, exemplar titles
   as text), same gates.
2. Two-lens pairs: far in topic, near in register, once section 23's
   per-medium caveat is settled.
3. The ranker learns from `ratings.jsonl` once enough exist to beat the judge
   under G2.

## Testing

Synthetic cone (random cloud + shared direction) for the sampler: ORTHO
rejects above threshold, NEAR pairs are neighbours, base draw is uniform.
Generator and judge stub `run_structured`. Deck test: no pool label leaves
the API. `just check` is the gate; search code is untouched so the retrieval
gate does not run.

## Naming

`drift` already names the interest-profile snapshot diff
(`synthesis.render_drift`). This feature is `lsd` everywhere.
