# P5 — The Loop Implementation Plan (#197)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Unattended operation — one loop thread in the hub becomes the single
writer of transitions; surfaces insert events and nudge; a launchd watchdog
outside the process can drop the loop inert.

**Architecture:** New `ytk/loop.py` hosts a testable single-tick function and a
thread driver started by the hub lifespan. `asks.answer_ask` stops
transitioning; the loop applies answer transitions. The idle sweep (parked
retry, intent-window expiry) runs inside the loop when stale. `ytk/watchdog.py`
plus a `ytk loop` CLI group deliver the breaker (`com.ytk.watchdog` launchd
plist) and `ytk loop status`. The digest's reserved `"loop": None` slot gets the
health line.

**Tech Stack:** Python stdlib threading + sqlite3, FastAPI (existing hub),
launchd plist per the `com.ytk.nightly` pattern, React digest strip.

**Spec:** `docs/architecture/curator-engine.md`, section "The loop (step 3)"
plus "Asks"/"Parked" and "Ledger and plans". Handoff: `/tmp/handoff-p5-XXXXXX.md`.

## Global Constraints

- Single writer: only the loop thread writes transitions (activity rows with
  non-null `to_state`). Every other process inserts into event tables
  (items, takes, answers) and nudges.
- The breaker lives OUTSIDE the hub process; the loop reads `loop.inert`
  before every transition and cannot clear it — only `ytk loop resume` can.
- Verbs are not reimplemented: the loop calls `evidence.read_item` and
  `curator.advance_item` as they exist.
- New modules pyright strict. Hermeticity seams for every new path
  (`YTK_LOOP_HEALTH`, `YTK_LOOP_KILL`, `YTK_LOOP_INERT`), autouse in conftest.
- Loop tests run fully stubbed (monkeypatch `advance_item` / `read_item` —
  P4 recorder pattern); no daemon thread does model work in tests; the thread
  is a thin driver around `tick_once`.
- No hub nav items; the loop strip lives inside the digest page (slot exists
  at `web/src/routes/index.tsx:140`).
- Frontend: Tailwind against observatory tokens; `vp exec vitest run`.
- store.py untouched; no eval re-stamp.
- Thresholds are stated guesses, written as named constants, re-sized later
  from the activity table: tick budget 10 items / 10 min; lease 15 min;
  poll 60 s; sweep every 6 h; parked-retry per-item cooldown 24 h, 10 items
  per sweep; ask-park window 14 days (quality kinds); daily token ceiling
  300_000; watchdog: 3+ rate-limit errors/h, 5+ errors/h, token ceiling.
- Decisions taken with the owner 2026-08-31: reflex sweep DEFERRED past P5
  (the sweep leaves a seam); `ytk add` returns immediately after
  capture + nudge (no poll, no synchronous read).
- One scope judgment beyond the handoff's bullet list, flagged: quality-kind
  asks (`transcript junk`, `blind item`, `grader bounce, twice`) park after a
  14-day window (spec, Parked: "An unanswered ask parks after a window") so
  the parked-retry sweep has a population and the digest's parked line means
  something. Intent asks are untouched by this (they expire to dropped at
  their own `window_days`).
- Consequence to surface at merge report: once P5 runs, "intent missing"
  asks older than their 7-day `window_days` auto-drop (spec-intended,
  "expires to dropped as reflex") — the freeze pile's clock starts.

### Task 2: Tick core — selection, lease, verbs, answer transitions

**Files:** `ytk/loop.py`, `tests/test_loop.py`.

**Produces:**
- `pending_answers(conn) -> list[sqlite3.Row]` — answers whose item's last
  state is still `asking`, in answer id order.
- `apply_answer(conn, answer_row) -> None` — writes the transition
  `asking -> answered|dropped` (actor `"owner"`, reason = choice), exactly
  the row `answer_ask` writes today (Task 5 removes it there).
- `next_advanceable(conn) -> sqlite3.Row | None` — priority: pending answers
  first (as items), then items at `answered` in answer order (covers the
  pre-P5 freeze pile and an interrupted advance), then `captured` newest
  first, then `read` with a take. Parked-with-retry-due is served by the
  sweep (Task 4), not the tick selector — one implementation of the re-gate,
  invoked when the sweep is due.
- `lease(conn, item_id) -> bool` — `UPDATE items SET lease_until = <now+15m>,
  tick_count = tick_count + 1 WHERE id = ? AND (lease_until IS NULL OR
  lease_until < <now>)`; returns rowcount truthiness. `clear_lease` nulls it
  and resets `tick_count` on a state change.
- `tick_once(conn) -> TickStats` (dataclass: advanced, errors, asked,
  stopped_reason) — loop: inert check, select, lease, dispatch
  (`captured` -> `evidence.read_item`; `answered`/`read` ->
  `curator.advance_item(conn, id, actor="loop")`), clear lease, write
  health; until budget (10 items / 600 s) or nothing advanceable.

Verb calls monkeypatched in tests (recorder pattern from
`tests/test_curator.py`). Errors: catch per item, activity row action
`"loop-error"`, no transition, item skipped for the rest of this tick.

  read_item; read-with-take routed to advance; lease blocks a second
  concurrent pick and expired lease unblocks; budget stops the tick;
  inert file stops before any transition; error recorded without transition.
- [x] Implement, pass, commit.

### Task 4: The sweep

**Files:** `ytk/loop.py`, `ytk/evidence.py`, `tests/test_loop_sweep.py`.

**Produces:**
- `evidence.retry_parked(conn, item_id, *, actor="sweep") -> bool` —
  re-runs gatherer + `quality_asks`; on pass writes the bundle, transitions
  `parked -> read` (no new ask; the tick's funnel raises intent if takeless
  via `asks.raise_intent_ask`); on fail records the attempt (activity, no
  transition) and stays parked. Never raises a duplicate ask.
- `loop.sweep(conn) -> SweepStats`:
  1. park stale quality asks: open asks of quality kinds older than
     `ASK_PARK_DAYS = 14` -> `asking -> parked` (actor `"sweep"`).
  2. parked retry: parked items whose park came from `transcript junk` /
    `blind item`, last retry attempt older than 24 h, capped at 10 per
    sweep, newest first -> `retry_parked`.
  3. intent expiry: open `intent missing` asks older than their payload
     `window_days` -> transition to `dropped` (actor `"sweep"`, reason
     `"intent window expired"`, detail json with url/title/non-answer),
     stamp `outbox.answered_at` (no `answers` row — answers are owner
     events). Reflex sweep: explicitly deferred; leave a
     `# reflex sweep lands after P5 (owner decision 2026-08-31)` seam
     comment at the duty list.
  4. stamp `last_sweep_at` in health.
- `sweep_due() -> bool` — last_sweep_at missing or older than
  `SWEEP_HOURS = 6`; checked on every wake and on start (laptop sleep
  coalesces).

- [x] Failing tests: stale quality ask parks; retry pass returns to read
  with no new ask row; retry fail stays parked with an attempt recorded;
  cooldown and cap respected; intent ask past window drops with archive
  detail and closed outbox row; young asks untouched; sweep_due staleness.
- [x] Implement, pass, commit.
